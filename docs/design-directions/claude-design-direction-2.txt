Act as a senior product designer. Create ONE high-fidelity, interactive design direction for the MAIN ADMIN / MANAGER DASHBOARD of “Line Net CRM”. Deliver actual visual prototypes, not a written design proposal. The interface must be in Georgian.

PRODUCT CONTEXT
Line Net is a Georgian technical installation and maintenance company. Its teams work on CCTV, fire safety, access control, networking, structured cabling and electrical systems. The CRM manages incoming service requests, orders, client sites, technician assignments, visits, maintenance schedules and payments.

This is a daily working tool for an operations manager, not a marketing website. The first screen must quickly answer:
1. What needs attention now?
2. Who is assigned to today's work, and who has capacity?
3. Which orders should I open or assign next?

SCOPE
Design the admin/manager homepage in the single visual direction specified below. Deliver a 1440px desktop prototype and a 390px mobile adaptation, with meaningful local interactions. The data is illustrative, not live.

SHARED NAVIGATION AND LANGUAGE
Use these Georgian labels:
დაფა · შეკვეთები · შემოსულები · განრიგი · ტექმომსახურება · კლიენტები · ანგარიშები · პარამეტრები.
Primary action: “ახალი შეკვეთა”.
Other useful labels: “მოქმედება სჭირდება”, “დაუნიშნავი”, “დღევანდელი ვიზიტები”, “შემსრულებლების დატვირთვა”, “ჩასაბარებელი”, “ბოლო შეკვეთები”, “დანიშვნა”, “ყველას ნახვა”.
Order statuses: ახალი → დანიშნული → მიმდინარე → შესრულებული → დახურული; გაუქმებული is separate.
“შესრულებული” and “დახურული” must remain distinct: work may be finished but awaiting manager review.
“სასწრაფო” is a priority, “ვადაგადაცილებული” is a due-date condition. Neither should be invented as a mutually exclusive order status.

CONSISTENT SAMPLE DATA
Use clearly labelled demo data:
- Active orders: 24 = 6 new + 8 assigned + 10 in progress.
- Overdue active orders: 3; this is a subset of 24, not another group added to the total.
- Completed this week: 18; 4 of these await closure/review.
- Today's visits: 7.
- Unprocessed incoming email requests: 5.
- Payments received this week: ₾12,400.
- Outstanding balance across all orders: ₾8,700.
The two financial figures have different time scopes: label them precisely and do not divide them into a misleading collection percentage. Do not invent growth percentages without a previous-period baseline.

DIRECTION 2 — DISPATCH DESK / დისპეტჩერის სამუშაო დაფა
Build a practical, moderately dense dispatch workspace organized around scheduling and assigning technicians. Use a dark navy navigation rail and a bright working canvas; warm orange is the primary dispatch/action accent.
Suggested palette: navigation #152A3A, background #F3F5F6, surfaces #FFFFFF, accent #C45B12, text #172C3B. Keep status colors restrained and text-labelled.
Composition: compact attention strip → an unassigned-order queue on the left (about 30%) → today's technician schedule on the right (about 70%) → short follow-up section for closure and overdue items. This layout must visibly differ from direction 1.
Show three named technician lanes on one readable time axis. Each visit block shows the job, client and time. Make overlaps visible without assuming route optimization exists.
Implement “დანიშვნა” with an accessible selector or drawer. A drag-and-drop interaction is optional; never make dragging the only way to assign work.
Finance should be behind a secondary overview section, not dominate dispatch.
Feeling: a clear workplace for coordinating a field team, with high information density and quick decisions.

TYPOGRAPHY AND UI QUALITY
Use FiraGO or another font with complete Georgian support, with an appropriate fallback. Prefer 14–16px body text, clear labels and 24–30px page headings. Do not squeeze Georgian labels into tiny uppercase controls or truncate essential client names.
Use a consistent spacing scale and an intentional hierarchy. Add icons only where they help scanning. Status must remain understandable without relying on color. Provide visible focus states and readable contrast.
Mobile needs prioritization, not a shrunken desktop: use compact navigation, stacked visit/order rows and usable touch targets. Keep urgent work and “ახალი შეკვეთა” easy to reach.
Show an honest empty inbox state, a loading state and a recoverable data error state as separate prototype states. A disconnected mailbox should say “ფოსტა არ არის დაკავშირებული”, not pretend to receive messages.

LOCAL PROTOTYPE INTERACTIONS
- Order selection opens a useful detail drawer.
- “დანიშვნა” lets the manager select a technician and updates the sample row/schedule locally.
- “ახალი შეკვეთა” opens a compact example form with required-field validation.
- If a time-period selector is shown, make it switch the illustrative data coherently. Current active/overdue counts remain explicitly labelled as current totals.
- Keep finance for admin/manager views. Do not add financial data to a technician view.
- Do not make real API calls, send emails, register accounts, change subscriptions or deploy anything.

DELIVERABLE
Produce the visual prototype of this direction with desktop and mobile versions, and the local interactions above. Show the typography, surfaces, spacing, table or schedule treatment, statuses, buttons and drawer through the actual screens. Start with the visual prototype, not a long written proposal. Keep the product UI in Georgian.
