## გაკეთებული სამუშაო — გეგმის რიგით

2. **შემსრულებლები:** `/my/board` და ქვედა ნავიგაცია; საკუთარი და კოლეგის დანიშვნის მოთხოვნა, მენეჯერის დადასტურება/უარი; თითოეულის ეტაპი და შენიშვნა; ყველა შემსრულებლის ჩაბარებამდე შეკვეთა მიმდინარეა. თანხა და სერვისები ჩანს, გადახდის ველები საერთოდ ამოღებულია შემსრულებლის მონაცემებიდან, მასალების თვითღირებულება დამალულია. საკუთარი პოზიციების ცვლილება მხოლოდ დანიშნულ/მიმდინარე შეკვეთაზეა შესაძლებელი.
3. **პრიორიტეტი და ერთეულები:** სასწრაფო → მაღალი → ჩვეულებრივი → დაბალი; ხელით არჩეული დალაგება შენარჩუნებულია; სწრაფი ცვლილება ისტორიით; ჩვეულებრივი პრიორიტეტი ნიშნად აღარ ჩანს. საერთო UnitInput იღებს სიიდან არჩეულ ან ხელით ჩაწერილ ერთეულს; რაოდენობები ათწილადია.

- ყოველი ეტაპის შემდეგ შესრულდა `npm run typecheck` და `npm test`; აღმოჩენილი ტიპის შეცდომები გამოსწორდა.
- საბოლოო შედეგი: **15 სატესტო ფაილი, 121 ტესტი — ყველა წარმატებული**.

## მეილების ჩართვა მფლობელის მიერ

1. შეავსეთ `/settings/company`-ში კომპანიისა და ბანკის რეკვიზიტები.
2. Microsoft-ისთვის დააყენეთ `OUTLOOK_SEND=1` და ხელახლა დააკავშირეთ იგივე ფოსტა Mail.Send თანხმობით; ალტერნატივაა გამართული SMTP.
3. გადაამოწმეთ კლიენტის ელფოსტა და ობიექტის „მეილს იღებს“ კონტაქტები; გამოიყენეთ შეკვეთის მეილის გადახედვა.
4. რეალური გაგზავნის გარემოში `CLIENT_MAIL_DRY_RUN` არ უნდა იყოს `1`.
5. მხოლოდ ამის შემდეგ ჩართეთ კლიენტის მეილები `/settings/company`-ში. ამ სამუშაოს დროს ჩამრთველი არ ჩართულა.

Graph-ის განხორციელება ეყრდნობა Microsoft-ის [reply](https://learn.microsoft.com/en-us/graph/api/message-reply?view=graph-rest-1.0) და [sendMail](https://learn.microsoft.com/en-us/graph/api/user-sendmail?view=graph-rest-1.0) დოკუმენტაციას.
