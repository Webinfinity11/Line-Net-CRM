# Outlook.com / Hotmail ფოსტის დაკავშირება

პირადი Outlook.com / Hotmail საფოსტო ყუთი შეიძლება იყოს უფასო — Microsoft 365 Business ლიცენზია ამ გზისთვის საჭირო არ არის. Gmail მისამართით Microsoft-ში შესვლა Gmail-ის წერილებს Microsoft Graph-ისთვის ხელმისაწვდომს არ ხდის.

CRM-ის კოდი უკვე შეიცავს მომხმარებლის თანხმობით დაკავშირებას (OAuth authorization code + PKCE). რეალური წერილების მისაღებად საჭიროა Microsoft-ის აპლიკაციის რეგისტრაცია და ანგარიშით თანხმობა.

## Microsoft-ის აპლიკაცია

აპლიკაციის რეგისტრაციისთვის საჭიროა Microsoft Entra კატალოგზე წვდომა და შესაბამისი უფლება. მარტო Outlook საფოსტო ანგარიშის შექმნა ამ წვდომას არ იძლევა გარანტირებულად. თუ რეგისტრაციისას გამოწერას, ბარათს ან გადახდას გთხოვთ, შეჩერდით; უფასო ფოსტა და დეველოპერის აპლიკაციის რეგისტრაციის წინაპირობები სხვადასხვა საკითხია.

არსებულ ხელმისაწვდომ კატალოგში:

1. Entra → App registrations → New registration.
2. სახელი: `Line Net CRM Mail`.
3. Supported account types: **Any Entra ID Tenant + Personal Microsoft accounts**, ან **Personal accounts only**.
4. პლატფორმა: **Web**. Redirect URI ლოკალურად: `http://localhost:3000/api/mail/outlook/callback`.
5. ონლაინ გარემოსთვის დაამატეთ იგივე ბილიკი საიტის HTTPS მისამართზე.
6. Microsoft Graph-ის **Delegated** უფლებები: `User.Read`, `Mail.Read`, `offline_access`. წერილების გაგზავნისა და შეცვლის უფლება არ გვჭირდება.
7. შექმენით client secret და შეინახეთ მისი **Value**, არა Secret ID. გაითვალისწინეთ ვადა.

## სერვერის პარამეტრები

`.env.local`-ში ან ჰოსტინგის დაცულ გარემოს ცვლადებში:

```dotenv
OUTLOOK_CLIENT_ID=
OUTLOOK_CLIENT_SECRET=
MAIL_TOKEN_ENCRYPTION_KEY=
BETTER_AUTH_URL=http://localhost:3000
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

დაშიფვრის გასაღების გენერაცია: `openssl rand -hex 32`. გასაღები არის 64 თექვსმეტობითი სიმბოლო. შეინახეთ საიდუმლოდ, სარეზერვო ასლთან ერთად. გასაღების შეცვლის შემდეგ ფოსტა თავიდან უნდა დააკავშიროთ. ეს მონაცემები GitHub-ში არ ატვირთოთ.

```bash
npm run db:migrate
npm run dev
```

`MICROSOFT_*` პარამეტრები მხოლოდ CRM-ში Microsoft-ით შესვლას ემსახურება. ფოსტის ახალი კავშირი იყენებს ცალკე `OUTLOOK_*` პარამეტრებს. ძველი `GRAPH_*` გზა კვლავ ხელმისაწვდომია ორგანიზაციის საფოსტო ყუთისთვის; დაკავშირებული Outlook მასზე პრიორიტეტულია.

## მომხმარებლის მოქმედება

1. CRM-ში შედით ადმინისტრატორით და გახსენით **შემოსულები**.
2. დააჭირეთ **Outlook ფოსტის დაკავშირება**.
3. Microsoft-ში აირჩიეთ ფოსტა და თავად დაადასტურეთ წაკითხვის ნებართვა.
4. დაბრუნების შემდეგ ჩანს დაკავშირებული მისამართი.
5. სხვა ანგარიშიდან გამოგზავნეთ საცდელი წერილი ამ მისამართზე და დააჭირეთ **შემოწმება ახლა**.

პირველ დაკავშირებამდე არსებული წერილები ავტომატურად არ შემოდის. შემდეგ Inbox-ში მიღებული ყველა ახალი წერილი ქმნის დაუმუშავებელ შეკვეთას, რომელიც ადმინისტრატორებისა და მენეჯერებისთვის ხილულია. ხელახლა დაკავშირება აგრძელებს ბოლო შენახული პოზიციიდან. დამუშავებული წერილები ხელმეორედ არ იქმნება. დანართებზე მოქმედებს არსებული 25 MB ლიმიტი.

**გათიშვა** შლის CRM-ში შენახულ დაშიფრულ წვდომის ტოკენებს, თუმცა უკვე შემოტანილ შეკვეთებს ტოვებს. Microsoft-ის მხარეს გაცემული ნებართვა შეგიძლიათ ცალკე გააუქმოთ ანგარიშის აპლიკაციების მართვაში. სხვა ფოსტის დამატებამდე არსებული უნდა გათიშოთ.

ავტომატური შემოწმება მუშაობს ყოველ 5 წუთში მხოლოდ მუდმივად გაშვებულ Node სერვერზე. Serverless ჰოსტინგზე დააყენეთ `INTERNAL_CRON=0` და გამოიყენეთ გარე scheduler ან ხელით შემოწმება. ლოკალური ფაილების საცავი serverless გარემოსთვის მუდმივი საცავით უნდა შეიცვალოს.

## გადამოწმება

ავტომატური ტესტები ამოწმებს OAuth state/session ვალიდაციას, PKCE, დაშიფვრას, ტოკენის შეცდომებს, წერილების გვერდებად მიღებას, გამეორებისგან დაცვას და კურსორის შენარჩუნებას შეცდომისას. რეალური Microsoft ანგარიშით სრული ცდა ცალკე საჭიროა, აპლიკაციის მონაცემების დამატების შემდეგ.
